# Forecasting estimands and representation

Primary estimand: p_theta(R_i,t+1:t+H | H_t), a distribution over **reported main-economy aggregate log-return paths** on a fixed grid. H_t contains only buckets whose end plus known publication/ingestion delay is ≤ decision time. Event time, interval start/end, upstream publication, fetched_at and first locally available time are separate. Backfilled history cannot prove real-time availability; delay sensitivity300/600/1800s is proposed, not measured.

For positive finite source-compatible side prices define P=(high+low)/2 when both sides are observed, log return r=log(P_t/P_previous_grid). Missing endpoints produce missing targets; no interpolation. Midpoint is a statistical price index. Secondary targets are each side's log price, cumulative log return, realized volatility, log1p directional volume and relative side-price difference (a spread proxy). Do not mix scalar guides with transaction aggregates.

Joint density p(Y_1,...,Y_H|H_t) differs from separately estimated p(Y_h|H_t). Use the same encoder and comparable parameter/compute budgets to isolate dependence. Recursive models propagate sampled innovations; direct independent models are a defined independence coupling, not evidence of actual temporal independence. Joint Gaussian covariance, Gaussian copula with fixed marginals, flow and time-shuffled flow samples isolate dependence from marginal accuracy.

From sampled positive-price paths estimate probability max_h P_h/P_0≥1.03, maximum drawdown>0.05, distribution of maximum and first sampled-grid target/downside crossing. The event 'ends ≥3% higher at24h' differs from 'ever reaches +3% by24h'. Within-bucket crossings, crossing order inside a bucket and executable limit returns are unobserved. Same-bucket target/stop is ambiguous; report bounds. Path risk requires a start price and earlier running maximum, not terminal returns alone.

Proposed primary grid hourly, H=24, history168h; secondary H=4 and daily H=7 after gates. All six user horizons remain candidates:5m and15m require validated 5m data;1h/4h/24h are hourly-grid targets;7d initially daily or168h, which are different estimands. Do not silently substitute a24h index for a rolling daily bucket. Fix grid before evaluation; missing labels cannot be silently assigned zero returns.

Use trailing per-item robust location/scale, fitted only on training history with a nonzero floor; compare raw log returns and volatility-scaled returns. Keep scale as conditioning and invert for price-domain scores. Add missingness mask, side age when actual last-trade time exists, time since last **observed bucket** otherwise, log1p volume, trailing volatility and calendar features. Volume-zero is not missing. Preserve integer price tick effects; small-price series may need discrete/hurdle treatment rather than continuous Gaussian likelihood. No log of zero/nonpositive prices; flag, do not silently clamp. Record API rounding as measurement uncertainty.

Item embeddings use historical universe with out-of-vocabulary handling; no current-only survivor selection. Global versus grouped versus per-item models is an experiment. Cross-item context must be lagged and historically available, with groups fixed using development data. Event features require event publication timestamps; later revised wiki descriptions cannot enter earlier forecasts. Current limits/metadata are audit-only absent valid dated history.

Retraining experiments: fixed weekly; expanding window; rolling90/365d; trailing-residual change detector calibrated on validation. Detectors see only resolved past forecasts, with cooldown7d and false-alarm budget set before test. No retrospective best regime selection. Falsification: if apparent improvements vanish after latency, liquidity or era controls, retire the feature/model claim.
